# 同步模型

## 当前闭环

客户端只采集输入意图，服务端是玩家位置和游戏结果的唯一权威来源。阶段 3 在权威移动闭环上增加了本地预测和远端插值：

```text
Godot 输入
  -> InputCommand(sequence, client_tick, move_x, move_y)
  -> C++ 接收与校验
  -> 固定 Tick 世界模拟
  -> WorldSnapshot(server_tick, acknowledged_input, entities)
  -> 本地实体：权威位置 + 未确认输入重放
  -> 远端实体：100 ms 快照缓冲插值
```

客户端不能把本地位置作为事实发送。服务端只接受合法输入，并在自己的时间轴上计算位置。

## 三种频率

| 控制项 | 阶段 2 基线 | 职责 |
| --- | ---: | --- |
| 模拟 Tick | 30 Hz | 服务端推进权威世界。 |
| 输入发送 | 30 Hz | 客户端发送当前输入意图。 |
| 快照发送 | 15 Hz | 服务端广播可显示的世界状态。 |

三者必须可独立配置。较高模拟频率不自动要求同频率完整快照广播。

## 阶段 3 规则

- 客户端预测和服务端模拟都使用毫米整数、每 Tick `100 mm`、边界 `±9000 mm`。
- X、Y 轴独立推进，对角输入暂不归一化。
- 旧 `server_tick` 整包丢弃；缓冲末端保持最新状态，不做远端外推。
- 预测误差按校正前位置到“权威位置加重放结果”的距离计算。
- 视觉校正线和诊断数据不能反向修改模拟或服务端状态。

## 后续演进

高频运行档下，`client_tick` 仍是输入排序基础；需要更细粒度输入时，通过新的协议版本增加明确的子 Tick 时间字段，不能复用未定义填充字节。当前服务端按 Tick 应用最近输入，阶段 4 增加战斗前应明确命令映射到哪个服务端 Tick。

## 并行开发边界

客户端任务可以实现输入采集、网络收发、实体显示和诊断 UI；服务端任务可以实现输入校验、世界模拟和快照生成。任何一方都不能单独修改 `shared/protocol/` 的既有字段语义。跨端消息变更应作为一项包含双方实现和测试向量的完整任务提交。
