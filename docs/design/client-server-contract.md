# 客户端与服务端契约

## 权威归属

| 数据或行为 | 所有者 | 客户端职责 |
| --- | --- | --- |
| 键盘、手柄等原始输入 | 客户端 | 采样并编码为输入意图。 |
| 玩家位置、速度和碰撞结果 | 服务端 | 接收快照并显示。 |
| 输入序号与客户端 Tick | 客户端生成，服务端确认 | 保留未确认输入，供预测校正与诊断使用。 |
| 世界 Tick 与实体集合 | 服务端 | 记录最近收到的权威 Tick。 |
| RTT、渲染诊断 | 客户端 | 显示并用于观察，不改变权威状态。 |

## 当前集成要求

客户端连接完成后，以配置的输入频率发送 `InputCommand`。输入只包含方向、按钮、序号和时间信息；不包含期望位置。

服务端为每个已握手客户端维护最小 `PlayerState`，在每个模拟 Tick 应用最后一个有效输入。快照包含足以绘制所有已连接玩家的 ID 与权威位置，并附带 `server_tick` 和已确认输入序号。

客户端收到快照后，本地实体从权威位置重放未确认输入；远端实体按本机接收时间延后 `100 ms` 插值。客户端不能发送预测位置，也不能让渲染平滑结果进入权威判定。

移动规则固定为毫米整数、30 Hz 下每 Tick `100 mm`、边界 `±9000 mm`、X/Y 逐轴裁剪。当前对角输入不归一化。任一端修改这些规则都必须同步更新另一端及测试。

## 失败处理

- 长度、版本、消息类型或字段范围不合法的数据报直接丢弃。
- 未完成 `Hello` 的端点不能提交游戏输入。
- 未知实体、重复或过期输入不得破坏其他玩家状态。
- 客户端无法收到快照时只更新诊断状态，不自行创建权威游戏结果。
- 待确认输入超过 256 条时保持队列有界并显示丢弃计数；此状态表示连接已不适合精确预测。

协议字段、长度限制和编码规则以 [`shared/protocol/protocol.md`](../../shared/protocol/protocol.md) 为准。
