# 高频 Tick 性能预算

## 运行档

| 模拟档 | 单 Tick 时间 | 使用时机 |
| --- | ---: | --- |
| 30 Hz | 33.333 ms | 阶段 2 的功能正确性基线。 |
| 64 Hz | 15.625 ms | 权威移动稳定后的第一档高频实验。 |
| 128 Hz | 7.8125 ms | 压力、延迟补偿和高同步实验档。 |

`64 Hz` 与 `128 Hz` 是可配置的实验档，不是所有地图、实体规模和部署环境的默认承诺。提高 Tick 前先确认现有档的输入、快照和实体数量可重复测量。

## 预算原则

Tick 预算不仅包含世界模拟，还包含本 Tick 内的网络收包、输入验证、序列化、快照发送和必要统计。为了吸收系统调度、缓存失效和短暂网络突发，P99 应保留明显余量；学习期目标分别是：

- 30 Hz：P99 Tick 小于 16 ms。
- 64 Hz：P99 Tick 小于 8 ms。
- 128 Hz：P99 Tick 小于 4 ms。

这些是本地实验的工程警戒线，不是线上服务等级协议。超过预算时，先定位成本，再决定降低快照频率、优化状态复制、减少工作量或调整模拟档。

## 必测指标

- Tick 时长 P50、P95、P99 与超时 Tick 数。
- 每 Tick 网络收包数量、输入积压和丢弃数量。
- 每秒输入包数、快照包数、上行/下行字节数。
- 快照大小、实体数量和后续 AOI 广播量。
- 客户端 RTT、快照年龄、插值延迟、预测误差和校正次数。

高频模拟不等于高频完整快照。输入频率、模拟频率和快照频率必须分别记录和调整，避免带宽或序列化成本掩盖真正的模拟瓶颈。
